# ADD-001: a synthetic detail attached to the head

Date: 2026-11-09. Status: Petz 4 renderer-observed/code-supported, not game-validated. Scottie and Siamese; same renderer/runtime as SMOKE-001.

## Procedure

Run `scratch/petz-local-venv/bin/python tools/addball_probe.py`. Append one authored marker row to each resolved Add Ball section, preserving all existing rows. Both samples already have 23 added balls, making the new ID 90 (67+23); this ID must be recomputed for other files.

Marker fields: head base, offset (-35,-50,0), color 125, outline color 244, no speckles/fuzz/texture, color group -1, outline mode -1, diameter 20, body area 0, add group 0, no size reference. Variants compare original; marker control; first Head Enlargement value +25; head Move (20,0,0); relative-size marker; relative-size marker with first Head Enlargement +25; omitted marker. Relative-size variants use diameter adjustment -8 and size-base-ball=head.

Forty-two direct asset loads cover seven variants in standing/sitting/lying. Twelve local MCP aligned comparisons cover appearance, head enlargement front/side, sitting movement side, relative size and omission. Render controls: seed 0, age 100, fatness 50; yaw/pose recorded per comparison. Eight comparison images were visually reviewed (both species: insertion, side enlargement, relative-size growth, omission).

Private evidence: scratch/research/add-001. [Tracked authored rows, fields, geometry and hash manifest](add-001.json). Fixed-span copies preserve other resource bytes; original game files remain untouched.

## Findings

- Appending the marker preserves every pre-existing ball's geometry. No master Num Ballz edit is needed in these samples.
- Body area 0 resolves to the head's area 8 while the marker is visible. Merely belonging to that area does not cause Head Enlargement to resize its ordinary diameter or stretch its offset in these tests.
- The ordinary marker's full geometry is identical between control and head-enlarged variants in all three numerical poses. Standing radii are 5 pixels Dogz / 4 pixels Catz.
- The marker follows parent movement, subject to integer scaling/rotation. Exact posed pixel displacement need not equal the parent's: the sampled Catz sitting Y displacements are 0 versus 2 pixels. Pre-body scaled displacement differs by at most one pixel per axis in these samples; subsequent body rotation can compound quantization.
- The optional size-reference field causes marker-radius growth to equal head-radius growth in all three poses. Standing marker radii change 17→22 Dogz / 18→24 Catz. These intentionally large probes establish a dependency, not an attractive final ornament.
- Omissions marks the marker invisible while keeping its computed position/radius and every prior ball's geometry. Its body area becomes 0 in this renderer. The row and ID still exist; visibility is not deletion.

Initial numerical assertions assumed exact parent/attachment pixel displacement. Measurements and code inspection showed separate integer scaling, then automatic after-tilt rotation; the final experiment checks pre-body rounding and records posed deltas instead of forcing exact equality.

## Limits and next work

No line connects this marker to another ball. Body-area inheritance, nonzero add groups/morphs, relative-to-added-ball chains, size limits, textures, native inheritance and runtime head tracking require dedicated tests. The optional size field's behavior is implementation evidence, not proven original-game support. Do not infer that every attached decoration will scale automatically with every head control.
