# EYE-002: iris and host omission combinations

Date: 2026-11-09. Scope: Petz 4 Scottie/Siamese, standing front/side. Renderer-observed and code-supported; not game-validated.

## Method

Run `scratch/petz-local-venv/bin/python tools/eye_omission_probe.py`. Seed-resolved private breed copies contain one four-branch synthetic omission block: control, right iris, right host eye, both. Dogz host/iris IDs are 32/38; Catz 15/28. Selected seeds are 2/1/0/3 for those branches in both species. Effective sections must equal control plus exactly the intended omission rows. All typed appearance fields except omissions/lines must match. Resource metadata, unrelated payloads and bytes outside the adult LNZ span are preserved by the copy writer.

Four local stdio MCP sheets cover yaw 0°/90°, standing default frame, age 100 and fatness 50. Each sheet aligns all four cells at common scale; only within-sheet pixel hashes are compared. Contact-sheet raster seed is fixed by the renderer. All four PNGs were visually reviewed at native resolution. Private inputs, PNGs and returned metadata: scratch/research/eye-002. [Manifest](eye-002.json) records hashes, controls, branch checks and runtime. Atomic resume verifies completed PNGs, breed sources/copies, master resources and Python fingerprint/version. Runtime reference is [VIS-001](vis-001.md); shared binary engines remain an unverified dependency.

At front view the asset's right host is viewer-left. Its omission removes that eye's visible outer region and overlay in reviewed images. The side-view hash differences confirm some contribution, without establishing that the full affected region is visible there. Parsed line counts remain 70 Dogz / 51 Catz in every branch, so this experiment introduces no incident-line removal.

Prepared commands retain a host overlay object even when the host is invisible. Iris command `visible` is already false in the control; host visibility becomes false in host/both variants. This is a later pipeline stage than VIS-001's posed geometry, which reported true for non-omitted iris geometry. The flags must not be treated as interchangeable or as proof of raster contribution.

## Code-supported explanation

At renderer checkout revision 9d72d7afd5f7460ef18133c6179caaf8055082d9:

- rendering/assembly.py marks paired irises invisible as standalone balls.
- rendering/preparation.py constructs the iris overlay on the host without a separate iris omission gate.
- rendering/composition.py draws overlays inside the eligible host-ball pass, which requires host visibility.

These paths explain why iris omission alone is ineffective in these previews and why host omission suppresses the overlay. The installed Python source fingerprint is recorded separately from the checkout revision; a matching hash on resume establishes implementation continuity, not native-game fidelity.

## Limits and authoring implication

Only each species' right pair, one breed and one standing frame were tested. Left pairs, duplicate eye wiring, malformed inputs, added eyes, young resources and other game versions remain open. Host omission is a broader edit than iris omission and is not a substitute when only the iris was requested. Keep GAP-004 open until independent native behavior is established. No renderer fix was made.
