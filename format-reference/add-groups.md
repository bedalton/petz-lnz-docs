# Added-ball groups and dormant geometry

Evidence: [MORPH-001](../experiments/morph-001.md), Petz 4 Scottie/Siamese. Default-state local MCP images plus explicit numerical renderer updates; native-game behavior unvalidated.

Add Ball column 13 is the add group. In the tested default state, group 0 is active and an unused group 15 starts at zero. The latter marker remains defined but is parked with radius zero; its visibility flag alone is still true. Check parked status, radius, group amount and omissions together when diagnosing invisible details.

Dormancy and omission differ. The dormant marker keeps a parsed incident connector, but the default image shows neither marker nor connector. An omitted marker has visible false and retains its geometry while incident lines are dropped during parsing. Both can produce identical pixels.

Direct Python `posed_geometry(..., morph_updates=((15, percent),))` checks at 0/25/50/100 scale the ordinary marker's local offsets and size. Full activation matches the static group-0 counterpart in this sample. These are explicit implementation controls, not an LNZ section assigning a percentage and not automatic game animation. MCP comparisons in MORPH-001 exercise only the default state.

Keep existing rows and compute IDs before changing groups. Activating a group can affect every member; the experiment first verified group 15 unused in stock additions. [MORPH-002](../experiments/morph-002.md) tests head-relative size 20 in group 15: offsets scale, but evaluated size stays zero, so every positive tested percentage uses the full referenced head radius. At 100% it matches a static relative-size-0 marker rather than static relative-size-20. [MORPH-006](../experiments/morph-006.md) revalidates this exact case on integration6c1d883 across Petz3/4/5 Scottie/Siamese, with144 numerical records and36 default-state MCP pairs. Native intended behavior is unresolved (GAP-005). [MORPH-003](../experiments/morph-003.md) tests groups14/15 with A/C sharing14 and B in15: final offsets/sizes are independent, and reversed distinct-group updates preserve posed geometry while transition traces can differ. Dormant head-area markers extend the evaluated prefix but stay parked; default pixels equal dormant area1 controls. [MORPH-004](../experiments/morph-004.md) finds equal final geometry can accompany different retained draw order:47/60 batch-versus-incremental histories differ in order, with equal final fills. Two repeated-frame controls also change order without morph updates. [MORPH-005](../experiments/morph-005.md) renders these histories: substituting retained order alone changes no pixels in60 cases. Historical full retained preparation changes121 pixels in ten Dogz sitting cases. Subsequent static-state isolation is recorded in [TEXTURE-001/002](../experiments/texture-002.md), with the current static matrix in [UPDATE-006](../experiments/update-006.md); those static replays do not revalidate every historical MORPH-005 history count. Native runtime implications remain untested. See [Add Ball fields](add-ball.md), [connected details](linez.md) and [visibility diagnosis](../visual-editing/visibility.md).

[MORPH-007](../experiments/morph-007.md) separates the size-reference sign gate from attachment validity in1,728 Petz4 cases. Any nonnegative reference suppresses grouped size updates;only earlier IDs supply a radius. A self/later/out-of-range reference or an earlier dormant marker can therefore leave an activated probe unparked and visible with radius0. Negative reference tokens(-1/-2) retain ordinary size scaling in these controls.

[MORPH-008](../experiments/morph-008.md) tests size-reference chains/cycles across six row permutations:fully grouped head-rooted chains can propagate head radius through earlier markers,but grouped cycles stay radius0. A dormant earlier root supplies no radius. Reversing distinct-group updates preserves fresh final geometry;reordering marker rows can change radii even with correctly remapped references. Petz4 renderer evidence only.
