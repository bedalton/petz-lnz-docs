# Mouth shaping: community claims and test boundaries

Reviewed 2026-11-15. Primary author: Carolyn Horn. Start at her [LNZ File Details index](https://homebody.eu/carolyn/downloabx/tutorials/tutorialbits/LNZdetails.htm); relevant sections are [third chunk: Face Extension](https://homebody.eu/carolyn/downloabx/tutorials/tutorialbits/LNZ3rd.txt) and [second chunk: Add Ball](https://homebody.eu/carolyn/downloabx/tutorials/tutorialbits/LNZ2nd.txt). The pages also discuss other games; the claims below concern the explicitly relevant Petz controls, with exact Petz versions unspecified by these passages.

| Attributed claim | Evidence level and project interpretation |
| --- | --- |
| Positive Face Extension brings the nose forward; sufficiently negative values can push it back through the head. Some connected parts do not follow, and movement can expose intersecting joins. | Source-reported. This is a useful hypothesis and a reason to review the entire muzzle. It supplies neither a safe numerical range nor controlled game validation for our assets. |
| An added tongue can need the optional size-reference column to avoid a visible gap; zero ordinary size need not mean it is dispensable. | Source-reported. Existing renderer relative-radius tests support a size-reference mechanism, but do not establish the specific tongue animation or historical Pug diagnosis. |
| The optional reference is also described as affecting behavior. | Source-reported only. Our static size/attachment checks cannot establish the scope of that behavioral claim. Preserve the original reference and require native motion evidence before changing it. |

Renderer work is indexed from the [mouth preservation guide](../visual-editing/existing-mouth-and-muzzle.md). A matching static preview cannot validate eating, panting, tongue-out, breeding or other game behavior. The project preservation requirement remains authoritative for authoring: retain functional anatomy and original dependencies when a requested shape exceeds an established recipe.

Private retrievals, response metadata and content SHA-256 values are in `scratch/research/mouth-sources/retrieval.json`. These are retrieval dates, not publication dates. The source text remains private; the public documentation records attributed summaries and links rather than reproducing tutorials.
